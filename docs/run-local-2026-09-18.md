# Chạy backend V1 tại máy local

Đây là hướng dẫn **để người dùng tự chạy**, không có tiến trình nào được tự
khởi động. Bản chốt và cách nối Power Automate được trình bày đầy đủ tại
[V1 và hai mốc distillation](phat-hanh-v1-va-distillation.md). Backend vẫn là
V1; V2.27 chỉ là CLI nghiên cứu, V3.1 chỉ là điểm so sánh development.

## Chuẩn bị một lần

Từ root dự án `C:\Intern AI SPS\meeting-intelligent`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
```

Tạo shared secret riêng trong thư mục Git ignore theo lệnh ở
[hướng dẫn phát hành](phat-hanh-v1-va-distillation.md#cách-chạy-v1-với-power-automate).
Không ghi OpenAI key hay Power Automate key vào source, commit, transcript
hoặc URL.

## Chạy backend và tunnel

Terminal PowerShell thứ nhất:

```powershell
cd 'C:\Intern AI SPS\meeting-intelligent'
$env:POWER_AUTOMATE_API_KEY = (Get-Content 'evaluation\runtime\power-automate-local\api-key.txt' -Raw).Trim()
$env:PIPELINE_VERSION = 'v1'
# Tùy chọn: $env:OPENAI_API_KEY = '<OpenAI API key>'
.\.venv\Scripts\uvicorn.exe backend.app.main:app --host 127.0.0.1 --port 8010
```

Terminal PowerShell thứ hai:

```powershell
& "$env:LOCALAPPDATA\cloudflared\cloudflared.exe" tunnel `
  --protocol http2 `
  --url http://127.0.0.1:8010
```

Mỗi lần tạo Quick Tunnel, đọc URL HTTPS mới trong terminal thứ hai rồi cập
nhật `ApiBaseUrl` của flow. Kiểm tra `/health`; endpoint job yêu cầu
`X-API-Key`. Flow gửi file binary qua
`POST /api/v1/meetings/jobs/process-file`, lấy `status_url` trong phản hồi
202 và GET đến khi `succeeded` hoặc `failed`. Chỉ ghi Lists khi thành công.
Job store local nằm trong bộ nhớ, nên restart Uvicorn sẽ mất job chưa xong.
Quick Tunnel không đảm bảo uptime hoặc URL cố định.

## Chạy không có OpenAI key

Không đặt `OPENAI_API_KEY` trong terminal backend thì pipeline V1 vẫn chạy
theo quy tắc, không gọi OpenAI. Các window mơ hồ chưa giải quyết có thể xuất
hiện trong diagnostics. Khi thêm key, chỉ backend gọi OpenAI cho fallback
được giới hạn; flow Power Automate vẫn chỉ dùng `X-API-Key` riêng của backend.
DeepSeek PAT thuộc quy trình sinh dữ liệu/thử teacher private và **không** là
provider của API production.
